# report-layout-standard — 研究报告排版规范（单一来源）

这是研究报告排版规范的**唯一权威版本**。WorkBuddy、Claude、ChatGPT、Grok 四个模型都从这里读、往这里写。

## 这是什么

经过数十轮迭代打磨出的研究报告排版强制标准，涵盖：

- 排版总原则（读者视角、简洁、单页自足）
- 低级错误清单（结构性 9 条 + 可读性 4 条）
- 图表排版规则（图内序号图下说明、数据标注自带时点口径）
- 颜色规范（方向色锁定 + 指标色 + 跨地区统一）
- 金融配色（涨红跌绿）
- 技术规则（防断句拆页）

## 同步协议（四个模型必读，铁律）

1. **单一来源**：本仓库的 `SKILL.md` 是唯一权威版本。任何模型改规范，只改这里，然后 commit + push。
2. **谁改谁 push**：任何一个模型修正了规范，立即 `git commit` + `git push`，不要只改本地。
3. **改前先 pull**：任何模型开始改之前，先 `git pull` 拿到最新版，避免覆盖别人的改动。
4. **不另起炉灶**：不得在各自平台上另存一份「自己的版本」，否则又会分叉、又需要人工搬运。

## 文件结构

- `SKILL.md` — 排版规范正文（权威）
- `scripts/终版排版验收.py` — 结构性门禁（越界/断句/拆页/内部路径泄露/繁体/页码漂移）
- `scripts/检测裸数字.py` — 可读性门禁（图内裸数字无时点标注）

## 各模型如何接入

- **WorkBuddy**：把本仓库 clone/pull 到 `~/.workbuddy/skills/report-layout-standard/`，作为用户级 skill。
- **Claude / ChatGPT / Grok**：各自把本仓库的 `SKILL.md` 内容作为项目规范/系统提示引用，并配置好读写本仓库的权限。

## 一句话总结

**改规范 = 改本仓库 + push；用规范 = 先 pull。谁改谁 push，改前先 pull。**
